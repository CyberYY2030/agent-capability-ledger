# Case Law

| Case | Rule | Generic case | Cost of violation |
|---|---|---|---|
| CASE-1 | Locate the first divergent gate from the authoritative definition; check every consumer of shared definitions. | A derived counter is correct in a view but wrong in the state transition. | The display looks fixed while downstream behavior remains wrong. |
| CASE-2 | When an artifact exists but is not delivered, trace the consumer chain gate by gate and preserve previously valid inputs. | A generated report is dropped by a later attachment filter. | Rewriting generation adds risk and still misses the actual loss point. |
| CASE-3 | Search globally for an old shared literal and run the broad gate after changing it. | A common limit changes in one module. | Tests, comments, and another consumer retain conflicting truth. |
| CASE-4 | Shared file domains run serially; one card owns one reversible commit. | Two workers edit the same registry and entrypoint. | Integration requires replay and unrelated changes leak across commits. |
| CASE-5 | A generic continuation or timeout never authorizes a destructive branch. | A task pauses before a history-changing operation. | Ambiguous urgency is mistaken for permission and recovery becomes harder. |
| CASE-6 | High-impact surfaces require design review, hard gates, layered validation, and honest completion labels. | A local check passes while a system walkthrough remains unavailable. | Local green is reported as system safety. |
| CASE-7 | A pull-based skill needs an explicit consumer in an always-loaded layer. | Installation and validation pass but the router never invokes the skill. | The contract exists on disk and is absent in behavior. |
